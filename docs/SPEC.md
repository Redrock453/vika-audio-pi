# Vika Audio Pi — спецификация v0.1

Дата: 2026-11-23. Статус: **draft / discovery**, не подтверждённый MVP.

## 1. Задача

Построить **автономный офлайн-аудиоплеер** на Raspberry Pi 3 Model A+ (512 МБ ОЗУ): аудиокниги, музыка, лекции, подкасты. Ни экран, ни телефон, ни постоянный интернет не требуются. Устройство должно работать при отсутствии сети и объяснять своё состояние голосом, если есть рабочий аудиовыход. Основной режим — локальное детерминированное управление; интеллектуальный голосовой ввод — необязательное расширение.

### Принципы
- Минимум зависимостей, графических интерфейсов и фоновых процессов.
- Надёжность закладок важнее количества функций.
- «Детерминированный скелет, ИИ только в суставах».
- Без публичных портов; SSH только с доверенных устройств, предпочтительно по ключу.
- Не хранить на GitHub пароли, сетевые ключи, аудиоколлекцию, SSH-ключи и подробные идентификаторы устройств.
- Не использовать и не менять прежнюю специализированную 32-ГБ microSD. Для проекта отдельная 64-ГБ карта.

## 2. Аппаратное окружение

| Элемент | Дано / требование |
| --- | --- |
| Одноплатник | Raspberry Pi 3 Model A+, Cortex-A53, 512 МБ RAM |
| ОС | Raspberry Pi OS Lite 32-bit, Raspbian 13 (Trixie) |
| Накопитель | microSD 64 ГБ с системой + локальная библиотека; при необходимости USB |
| Wi-Fi | Нужен для setup/SCP/rsync, но не для прослушивания |
| SSH | Уже работает с T450 по ключу |
| Аудиовыход | Две гарнитуры: Bluetooth **HD-610** и **проводные JBL с кнопкой**; штатный аналоговый выход 3,5 мм Pi — только воспроизведение |
| Кнопки | На проводных JBL есть встроенная кнопка; её поддержка со штатным разъёмом Pi **отсутствует**. Для управления использовать GPIO/USB HID или проверенный USB-адаптер, который действительно передаёт события кнопки |
| Микрофон | Наличие микрофона на проводных JBL ещё не подтверждено; даже при его наличии штатный разъём Pi не принимает микрофонный сигнал. Требуется совместимая USB-звуковая карта/USB-микрофон или проверенный Bluetooth HFP/HSP |
| Питание | 5 В подходящей мощности / пауэрбанк; время работы проверить опытно |
| Bluetooth | BlueZ + BlueALSA — предпочтительный headless маршрут; подтвердить устойчивость |

**Проверено 23 ноября:** Wi-Fi и SSH работают, ОС Trixie, Bluetooth контроллер обнаружен и разблокирован; гарнитура видна как HD-610. При первоначальном сопряжении произошёл разрыв с ошибкой `a2dp-sink profile connect failed: Protocol not available`. `bluez-alsa-utils` установлен, `bluealsa.service` активна; успешное длительное аудиоподключение и звук **ещё не подтверждены**.

## 2.1. Две гарнитуры: факты и гипотезы

- **HD-610:** Bluetooth-устройство, реально обнаруженное через BlueZ. Устойчивое A2DP-воспроизведение пока не подтверждено.
- **JBL проводные:** отдельная гарнитура пользователя со встроенной кнопкой. Тип штекера, точная модель, наличие микрофона и обработка кнопки ещё не проверены.
- Проводной звук можно испытать через аналоговый выход Pi. **Это не означает, что кнопка или микрофон будут работать**. Для проверки кнопки/микрофона нужен совместимый интерфейс с вводом и подтверждённой поддержкой событий; нельзя предполагать такую поддержку у любого USB-TRRS адаптера.
- Базовая архитектура не зависит от модели наушников: при потере Bluetooth можно использовать проводное воспроизведение, а кнопочное управление реализовать отдельно.

## 3. Сценарии пользователя

1. Подача питания → система готова без экрана/смартфона; никаких неожиданных громких звуков.
2. Короткая кнопка → продолжить последнюю книгу с сохранённой позиции или пауза.
3. Длинное нажатие / дополнительные кнопки → сменить главу, перемотать ±30 с, громкость.
4. Потеря Bluetooth → сохранить позицию, не терять управление; возобновление после соединения по явной политике.
5. Импорт книг по USB или SCP/rsync с ноутбука, без дополнительных облачных аккаунтов.
6. Офлайн-подсказки «Готово», «Глава …», «Пауза», «Заряд/ошибка» (последнее только если доступно соответствующее оборудование/датчик).
7. Таймер сна 15/30/60 минут.
8. Опционально: push-to-talk → короткая офлайн-команда; без микрофона устройство остаётся полностью работоспособным.

## 4. Приоритеты и критерии приёмки

| ID | Приоритет | Функция | Тест приёмки |
| --- | --- | --- | --- |
| F01 | P0 | Офлайн MP3 | 30 минут без сетевого соединения и обрывов |
| F02 | P0 | Закладка на книгу/главу | После штатной перезагрузки место восстановлено с точностью ±5 с |
| F03 | P0 | Запись прогресса каждые 10–15 с и при паузе | После внезапного отключения потеря позиции ≤30 с |
| F04 | P0 | Без экрана/телефона | Playback/пауза запускаются физической кнопкой при отключённом Wi-Fi |
| F05 | P0 | Плавные безопасные состояния | Нет неожиданных автовоспроизведений и перезапусков в цикле |
| F06 | P1 | Bluetooth A2DP | Три цикла выключения/включения HD-610, переподключение воспроизводимо |
| F07 | P1 | Проводной выход | Воспроизведение при отключённом Bluetooth |
| F08 | P1 | Навигация, громкость, перемотка | Без экрана и SSH |
| F09 | P1 | Офлайн TTS оповещений | Проверить разборчивость русского и украинского, громкость и прерывания |
| F10 | P1 | Импорт коллекции | Книги добавляются, старые закладки сохраняются |
| F11 | P1 | Таймер сна | Остановка с сохранением позиции |
| F12 | P2 | Микрофон и offline STT | Строгая грамматика, измерить ложные срабатывания в реальных условиях |
| F13 | P2 | AVRCP на наушниках | Кнопка гарнитуры срабатывает только после подтверждённого профиля |
| F14 | P2 | Интеграция с Викой | Отдельный, строго необязательный локальный/приватный канал команд |

MVP — F01–F05, затем F06–F11. **Не блокировать готовность MVP** ожиданием Bluetooth, голосовых команд или интеграции с Викой.

Форматы: MP3 — обязательно; M4A/M4B, OGG, FLAC — по результатам проверки движка и закладок.

## 5. Архитектура

```text
GPIO / USB HID / [позже AVRCP] / [позже STT]
                     |
          vika-control (Python, non-root)
         FSM + input debounce + action router
                |             |
      media adapter       SQLite bookmarks
        MPD or mpv        атомарные транзакции
                |
         audio router <--- офлайн TTS (eSpeak-NG / записи фраз)
           |     |
           v     v
        BlueALSA ALSA analog
           |
         HD-610
```

**Не делать сейчас:** собственный декодер, веб-панель, полноценную LLM, обязательное облако. Отбор `mpd` / `mpv` провести по тестам на конкретной Pi. HTTP не слушать; управление через локальный Unix socket и systemd.

Состояния: `BOOT -> IDLE <-> PLAYING <-> PAUSED`. Аварийные: `OUTPUT_LOST`, `ERROR_SAFE`, `SHUTDOWN`. При восстановлении запуска — **PAUSED**, не автозвук.

SQLite: `book_id, media_path, chapter, position_ms, updated_at, completed`. Запись по таймеру, при паузе, смене файла и завершении. WAL/rollback и fsync выбирать после испытания скорости и надёжности microSD. Не делать частых лишних записей.

Для микрофона: встроенный 3,5-мм разъём не принимает аналоговый микрофон. Bluetooth HFP и A2DP могут требовать переключения профиля и ухудшать звук. Предпочтительный исследовательский вариант — отдельный USB-микрофон с push-to-talk.

## 6. Voice scope

- **Вывод**: короткие голосовые подсказки offline (eSpeak-NG или заранее записанные файлы); не допускать наложения на аудиокнигу без микширования/ducking.
- **Ввод P2**: «пауза», «играй», «назад», «дальше», «громче», «тише», «таймер 30 минут». Сравнить PocketSphinx с малым словарём и Vosk small *только после измерения памяти*. Не требовать постоянно работающего распознавания.
- **Кнопки** остаются первичным контролем; голос — дополнительный.

## 7. Ресурсы и безопасность

- Целевой **дополнительный** бюджет RAM для плеера, контроллера и TTS — до 120 МиБ (гипотеза, требуется замер). Не рассчитывать на swap.
- Цель: готовность после включения ≤60 сек; измерить на реальной карте, не обещать заранее.
- Тест: 10 перезапусков, 3 контролируемые потери питания, 3 переподключения наушников, 30 минут аудио.
- Логи без приватной аудиотранскрипции и секретов, ограниченный размер; медиа вне репозитория.
- До оптимизации измерить RSS/CPU, ошибки ALSA/BlueALSA, CPU температуры, падения, качество сохранения позиции.
- Любые действия над разделами/прошивкой — отдельная явная проверка цели и подтверждение; не затрагивать старую 32-ГБ карту.

## 8. Решение о готовом OSS

**Исследовать в первую очередь:** Phoniebox и One Button Audiobook Player; также Lauschkiste (alpha) и voicetunes (push-to-talk). Они **не объявлены совместимыми с Trixie/3A+** без испытаний. Подробности в [OSS_RESEARCH.md](OSS_RESEARCH.md).

## 9. Definition of Done (MVP)

MVP принимается только если выполнение P0 продемонстрировано *на реальном Pi 3 A+*: офлайн, без смартфона, с кнопкой, восстановлением позиции и логом тестов. GitHub README или успешная установка пакетов сами по себе не являются приёмкой.
